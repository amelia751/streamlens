# YouTube — Netflix-operated channels

## Attribution

| Field | Value |
|-------|-------|
| **Source** | [YouTube Data API v3](https://developers.google.com/youtube/v3) |
| **Auth** | `secrets/youtube.env` (`YOUTUBE_API_KEY`, GCP `pctg-503822`) |
| **Scope** | Public video/channel statistics only. No OAuth, no private user data |
| **Verified** | 2026-09-06 |

## This source does not use GCS

Every other source lands in `gs://streamlens-data/raw/` first. YouTube does not,
and the reason is legal rather than architectural.

The raw zone is immutable and never overwritten. The [YouTube API Developer
Policies](https://developers.google.com/youtube/terms/developer-policies)
(III.E.4) require public API data to be **deleted or refreshed within 30
calendar days**. Those two rules cannot both hold for the same bytes, so YouTube
writes straight to ClickHouse, where rows carry a TTL and expire on schedule.

This is the one deviation from the medallion flow in `data/README.md`, and it
costs us something real: `videos.list` returns *current* statistics only, so
history that is not captured cannot be re-fetched later. We accept that in
exchange for compliance.

## Retention

The policy draws its line between content and statistics, so the schema does too.

| Data | Retention | Basis |
|------|-----------|-------|
| Titles, descriptions, tags, comment text | 30 days, always | III.E.4 |
| View / like / comment counts | 30 days | III.E.4 |
| ↳ same, for audited developers | 36 months | [derived metrics amendment](https://developers.google.com/youtube/terms/derived-metrics-policy) |
| `netflix_title_id` ↔ TMDB bridge | indefinite | not YouTube data |

We currently run **strict 30-day retention**, which needs no application or
approval. Adopting the 36-month statistics window requires an audit and quota
extension; two `TTL` lines in `scripts/youtube/schema.sql` are marked
`AUDIT-GATED` and are the only things that change.

Two further constraints worth remembering:

- Derived metrics (velocity, momentum) must be labelled as generated by us, not
  sourced from YouTube.
- The policy restricts *aggregating* API data across channels you do not own.
  Roll-ups across all 44 channels should stay private or be clearly labelled.

## The channel roster

`scripts/youtube/channels.json` pins **44 Netflix-operated channels** —
183,143 videos, ~200M subscribers — keyed on the immutable `UC…` channel ID.

**Handles are informational only and must never be used for identity.** Six
obvious guesses resolve to squatters or dead accounts:

| Guessed | Actually resolves to | Real channel |
|---------|---------------------|--------------|
| `@netflixjunior` | "FRUSTRATED GAMER X", 5 videos | `@netflixjr` |
| `@theswoon` | "tuskde", 0 videos | `@netflixkcontent` |
| `@netflixgeeked` | 3 subscribers | `@netflix_geeked` |
| `@netflixlatinoamerica` | "AYB", 1 video | `@netflixlatam` |
| `@netflixafrica` | 16 videos | `@africaonnetflix` |
| `@netflixuk` | no such handle | `@stillwatchingnetflix` |

Netflix does not run one channel per country. The roster splits into 30
regional, 10 genre/audience, 1 co-brand, 1 single-title, and 2 corporate
channels. Canada, Australia/NZ and the UK have been consolidated away —
`Still Watching Netflix` is the former Netflix UK & Ireland, now a global
English brand and the largest channel of the 44 by upload count.

Two channels were checked and **rejected**: `@netflixdecoded` (a Hindi
fan-review channel) and `@swoonbites` (a ReelShort affiliate account trading on
the retired Swoon brand). Both are recorded in the registry so they are not
re-added.

Verification needed three independent signals, because each alone is wrong.
Handle lookup catches squatters. Description boilerplate produces false
negatives on localised channels — Netflix Korea and Netflix MENA carry the
corporate text in Korean and Arabic. "Does it link to netflix.com" produces
false negatives on Netflix Jr., Netflix Family and Investor Relations, which
are official but do not link out.

## The Netflix title ID

Netflix writes its own catalog identifier into video descriptions:

```
Watch on Netflix: https://www.netflix.com/title/81991579
```

It appears on **~60% of videos overall**, and 74% on regional channels — 94% on
Netflix Is A Joke, 87% on the main channel. It is absent on kids and sports
content, which is not catalog-driven.

This is the strongest identity anchor in the project. It clusters every trailer,
teaser and clip for one title across all 44 channels and 20+ languages with no
fuzzy matching. A single observed example: title `81611855` has 28 clips across
26 channels — one coordinated global campaign, visible in one row.

Mapping those IDs to TMDB has **no public authority behind it**. The bridge is
reconstructed by matching title and year against TMDB data we already hold, so
every row carries a `match_method` and `confidence`, and must be presented as
reconstructed rather than ground truth.

## Schema notes

- Metric snapshots are **append-only**. A snapshot at T is a new observation,
  not a correction of T-1, so deduplicating would destroy the series.
- Counters are `Nullable(UInt64)` and never `DEFAULT 0`. The API **omits** the
  field when a creator hides likes or disables comments; collapsing absent to
  zero manufactures a huge negative delta the moment that happens. A
  `stats_flags` bitmask records why a value is null.
- View counts can go **down** when YouTube purges bot views. Deltas are clamped
  at zero, but the drop is preserved as `purge_events` — it is an editorial
  signal, not noise.
- About a third of uploads are Shorts, so `is_short` is a first-class column.
  Mixing Shorts and trailers in one view-count metric is meaningless.

## How to reproduce

```bash
python3 scripts/youtube/sync.py --plan       # quota estimate, no API calls
python3 scripts/youtube/sync.py --backfill   # first run, ~7,300 units
python3 scripts/youtube/sync.py              # incremental cycle
```

Schema: `scripts/youtube/schema.sql`. Registry: `scripts/youtube/channels.json`.

## Quota

The default 10,000 units/day is ample, but only if `search.list` is avoided —
since June 2026 it sits in its own bucket capped at 100 calls/day. Everything
the pipeline needs costs 1 unit and batches 50 items per call.

Upload discovery uses per-channel **RSS feeds**
(`youtube.com/feeds/videos.xml?channel_id=…`), which cost **zero units** and
were confirmed working on all 44 channels, with `playlistItems.list` as fallback.

| Phase | Units |
|-------|-------|
| One-time backfill (183k videos) | ~7,300 (0.73 days) |
| Steady state, 4 cycles/day | **~263 of 10,000 (2.6%)** |

Refresh is tiered by age: videos under 7 days on every cycle, under 90 days
daily, older every 21 days. The cold cadence is 21 rather than 30 days so every
row is renewed before its TTL fires — the same pass satisfies both freshness and
the policy's delete-or-refresh requirement.

## Compliance checklist

- Public statistics and public comments only; never OAuth or private data
- Never print, log, or commit `YOUTUBE_API_KEY`
- Label derived metrics as ours, not YouTube's
- Keep cross-channel aggregates private or clearly labelled
- Do not write YouTube payloads to `gs://streamlens-data/raw/`
